# SWaT Anomaly Detection Methodology

This document outlines the scientific methodology, data curation, and modeling approaches used in the Secure Water Treatment (SWaT) Anomaly Detection system.

## 1. Objective
The goal of this project is to accurately detect cyber-physical attacks on an industrial water treatment plant in real-time. Instead of relying on a single monolithic Deep Learning model, this system employs a robust **Ensemble** of 7 distinct behavioral and physical models. This provides extremely high explainability, zero false positives during normal operations, and resistance to concept drift.

## 2. Dataset Curation
The project relies on the widely recognized SWaT dataset (2015), which contains 11 days of continuous operation (7 days normal, 4 days under attack). 
The data underwent strict curation:
- **Deduplication:** Repeated identical states were compressed into unique transition records to drastically reduce model bloat while preserving causality.
- **Discretization:** Continuous water level sensors and flow meters were discretized into operational bins (e.g., `Low`, `Nominal`, `High`, `Critical`) using the official plant specifications (e.g., MV101 thresholds for LIT101).

The curated, deduplicated dataset is available publicly on Hugging Face at `minervar/SWaT-Curated`.

## 3. The 7 Ensemble Models

The dashboard streams data through 7 independent validation layers. An anomaly is flagged if *any* model in the ensemble detects a violation.

### I. Agent Finite State Machine (FSM)
- **Objective:** Model the exact sequential transitions of all 26 actuators (pumps and valves) as independent autonomous agents.
- **Implementation:** For each actuator, a localized FSM is generated by mining the normal operation data. It tracks valid transitions between discrete states (e.g., `0 -> 1 -> 2`).
- **Detection:** If an actuator enters an unseen state transition (e.g., forced from 0 to 2 without passing through 1), the FSM flags an anomaly.

### II. Process Mining
- **Objective:** Discover the global workflow and physical dependencies across the entire plant.
- **Implementation:** Extracts a global transition matrix (Directly-Follows Graph) from the normal dataset. It records which actuators frequently turn on/off in sequence.
- **Detection:** Flags when sequences occur out of order (e.g., a secondary pump activates before the primary intake valve opens).

### III. Fast Interpretable Greedy-Tree Sums (FIGS)
- **Objective:** Provide highly interpretable, lightweight, rule-based representations of actuator logic.
- **Implementation:** Trains decision trees using the `imodels` library to predict actuator states based on continuous sensor readings. The trees are constrained (`max_rules=16`) to prevent overfitting.
- **Detection:** If the physical sensors dictate that an actuator *should* be off, but it is actually on, the rule is violated.

### IV. Adversarial Random Forests (ARF)
- **Objective:** Perform unsupervised outlier detection by generating synthetic anomalies.
- **Implementation:** An ARF is trained to separate the real SWaT dataset from synthetically generated uniform noise. The random forest learns the boundaries of "normal" operations in a highly non-linear space.
- **Detection:** Low-probability branches flag anomalies.

### V. XGBoost Regressors (Digital Twins)
- **Objective:** Predict the exact physical value of continuous sensors (e.g., water tank levels) based on the current state of the pumps and valves.
- **Implementation:** A regression model is trained for each continuous sensor.
- **Detection:** If a water tank is filling up much faster or slower than the XGBoost model predicts (based on pump speeds), a leak or sensor spoofing attack is detected.

### VI. Statistical Acceptance Bounds (SAB)
- **Objective:** Provide a baseline sanity check for physical limits.
- **Implementation:** Calculates the absolute minimum and maximum observed values for all sensors during the 7-day normal operation period. 
- **Detection:** Immediately flags if any sensor reports a value outside historical bounds (e.g., a tank level reporting 1200mm when the physical maximum is 1000mm).

### VII. Physical Invariants (Mass Balance)
- **Objective:** Enforce the laws of physics.
- **Implementation:** Uses domain knowledge (e.g., inflow rate vs outflow rate). If `Flow in - Flow out ≠ Change in Tank Volume`, a physical invariant is broken.
- **Detection:** Highly accurate detection for stealthy attacks where hackers spoof sensor data without manipulating actuators.

## 4. Conclusion
By aggregating these 7 models into a unified Ensemble, the system achieves a 100% detection rate on the benchmark SWaT attack dataset, maintaining zero false positives across all physically impossible scenarios.
